# 判断記録

## D-001 複数 PC とウィジェット単位の対象選択

要求の「事前に設定した PC」を一台に限定しない。複数 PC を保存し、ウィジェットを置くときに一台を選ぶ。アプリの画面は一覧と編集画面に絞る。設定変更後にウィジェットを作り直す必要がないよう、ウィジェットは PC の ID を保持する。

## D-002 ネットワーク設定

自動探索は機種・ネットワーク差と権限が増えるため設けない。送信先 IPv4 と UDP ポートを利用者が指定する。既定値は汎用の `255.255.255.255:9` とし、届かない環境ではサブネットのブロードキャストを指定できるようにする。

## D-003 実装基盤

初版は Android フレームワークの Java と XML リソースを使用する。追加の UI ライブラリを使わず、画面と 1 × 1 RemoteViews ウィジェットを小さく保つ。ビルドには Android Gradle Plugin 8.13.2、Gradle 8.13、JDK 17、compile/target SDK 36 を用いる。Android 17 のローカルネットワーク権限は target SDK 37 への更新時に実装する。現行 target SDK 36 では INTERNET 権限で LAN 送信が許可されるという [Android 公式説明](https://developer.android.com/privacy-and-security/local-network-permission) に従う。

## D-004 送信結果の表現

UDP は相手からの受領応答がない。UI は「送信しました」「送信できませんでした」と表示し、「起動しました」とは表示しない。

## D-005 保存と削除

設定はアプリ専用の SharedPreferences に JSON として保存する。設定件数が少なく検索・共有が不要なためデータベースを使わない。PC 削除後もウィジェット枠は残し、設定を促す状態にする。

## D-006 画面の構成と外観

ホームは PC 一覧と追加ボタン、編集は単一フォーム、ウィジェット設定は PC 選択だけにする。色は深い青緑を操作色、淡い灰色を背景、白をカードに統一する。画面遷移や装飾を増やさず、最初の起動から機能の入口が分かる構成を優先する。小さなウィジェットではアイコンと省略可能な一行の PC 名だけを表示する。

## D-007 継続的な確認

ローカル作業環境に Android SDK がないため、GitHub Actions で毎回単体テスト・ビルド・Lint を実施し、Debug APK を保存する。エミュレーターの起動確認と画面画像も自動化する。実際の LAN と PC の電源操作は、利用者の環境で別途確認する。

## D-008 ウィジェットの送信フィードバック

ウィジェットを押した直後に「送信中」、UDP 送出後に「送信済」または「失敗」をアイコンとともに約 3 秒表示し、その後 PC 名に戻す。既存の短い Toast も補助として残す。通知欄への通知は Android 13 以降で実行時権限が必要となり、許可されない端末では主目的のフィードバックを保証できないため採用しない。更新は対象ウィジェットだけに行い、連続タップでは後の操作の状態を優先する。UDP の送出成功と PC の起動成功は区別する。[Android ウィジェット更新](https://developer.android.com/develop/ui/views/appwidgets/advanced)、[通知権限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)。

## D-009 ランチャーアイコンの形状対応

Android 8 以降の適応型アイコンを使い、背景を緑の全面レイヤー、電源マークを安全領域内の前景レイヤーに分ける。丸、角丸四角、その他ランチャーのマスク形状で白い余白を出さない。テーマ適用アイコン用に単色レイヤーも用意する。[Android の適応型アイコン仕様](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)に従う。
